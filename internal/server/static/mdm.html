Enrollment links

A Mac enrolls by opening a link in Safari, then approving the downloaded profile in System Settings → Privacy & Security → Profiles (user-approved enrollment). Each link works a set number of times and then expires, so a Mac nobody sent a link to cannot enroll. Every download counts as one use.

Apple MDM

—

You can see this setup; changing it needs integrations.manage.

1. Push certificate

Apple wakes an enrolled Mac only for a server holding an MDM push certificate. Apple issues one only for a request signed by an MDM vendor, which mustra cannot be: make the request here, have it signed by a vendor you have an agreement with (your own Apple Developer Enterprise account's MDM CSR role, or a vendor signing service), upload the signed request at identity.apple.com with an Apple ID the organization keeps, and bring the certificate back here. Renew it every year with the same Apple ID. Help → Apple MDM walks through it.

2. MDM CA

Each enrollment link hands the Mac its own identity certificate, issued by a CA mustra keeps in its credential vault. The Mac signs every message with it, which is how the server knows which Mac is talking, even behind a proxy that ends TLS. Created once; replacing it would cut off every enrolled Mac.

3. Profile signing (optional)

Unsigned, the enrollment profile installs but shows as unverified. A certificate the Macs already trust, such as the console's TLS certificate, signs it as verified. Paste the certificate (and its chain) and its key.
