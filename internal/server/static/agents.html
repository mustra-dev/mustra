Endpoints behind the current version

How updates work The endpoint downloads the new build and checks it against this deployment's update signing key, which it pinned when it enrolled; it refuses anything unsigned, altered or older. If the new build does not start and reach the console, the endpoint puts the previous one back. The stored identity survives, so it stays the same machine with the same history. The endpoint drops off for a moment while the agent restarts, and the version here updates when it comes back. An endpoint that is offline, or on an agent too old to have been asked this way, has to be reached some other way.

Manual install

A new endpoint enrolls with an enrollment token: it presents the token once, receives a credential of its own, and the token is spent. The installer carries no shared password, and refuses to install a new endpoint without a token. A token is shown once; create one per rollout, with as many uses as machines you are about to install.

These endpoints report inventory, compliance and vulnerabilities, and take the updates their package manager offers, but refuse anything else from the server: Direct Connect, deployments, custom sensors, Enforce and agent updates. A compromised server can't run code on them. Only an administrator on the endpoint can undo it, and you update the agent by running the installer there.

Administrative rights

        

          The agent needs full rights on an endpoint — it installs and removes software, reads every process and
          service, and manages system services — so it runs as a root systemd unit or OpenRC service, a root LaunchDaemon, or a
          LocalSystem Windows service. All three installers refuse to run unprivileged rather than half-installing.
        

        

          Two platforms need something beyond that, and each endpoint measures and reports its own gaps under the
          Privileges tab:
        

        
    
          
  • 
            macOS gates parts of the filesystem behind TCC, which root does not bypass. Full Disk
            Access closes the gap, and there are exactly two ways to grant it.
            
    
              
    
                
    By hand — right for a handful of Macs
    
                System Settings → Privacy & Security → Full Disk Access → + → press
                Cmd+Shift+G, enter /opt/mustra-agent, choose mustra-agent.
                Takes about thirty seconds and needs no infrastructure.
              
    
              
    
                
    By MDM — right once there are enough Macs to matter
    
                Push the profile below through the MDM the Mac is enrolled in. Apple honours a TCC payload
                only from an enrolled MDM — installing this file by double-clicking it will not work, by
                design. Manual enrolment counts, as long as the user approves it.
                
    
                  Download PPPC profile
                
    
              
    
            
    
            
    
              Each endpoint reports which of these applies under its own Privileges tab — an
              unenrolled Mac is told to grant it by hand rather than pointed at a profile it can't use.

  • 
            Windows hands a LocalSystem token privileges that arrive disabled —
            SeDebugPrivilege, SeBackupPrivilege and the rest do nothing until a process enables them. The agent

Client configuration profiles

        
Settings pushed to the agents in a group: sensor interval, log level, and a random delay that spreads reports across the interval. Where several profiles cover an endpoint the highest priority wins. Profiles are re-applied every five minutes, so an agent that restarts with old flags converges. Agents older than 0.47.0 do not take profiles and show as drifted. A setting left at 0 or blank is left alone on the endpoint.

Retention

        

          An endpoint that stops answering is retired, not deleted: the row and everything recorded about it stay,
          managed goes false, and Last Seen says when it was last true. What a decommissioned machine was running is
          exactly the question somebody asks months later. An endpoint that registers or heartbeats again comes back on its
          own, with its history. Target retired ones in a computer group with managed equals false.

Attributes

        

          What you know about an endpoint that no sensor can report — owner, cost centre, location, whether it may be
          rebooted in the day. Each one becomes a targeting key: an attribute named owner is
          attr.owner in a computer-group rule, and a column named attr_owner in exports and
          reports, so a report can be grouped by it. A name cannot be changed after it is created, because every group
          targeting it would break silently.
