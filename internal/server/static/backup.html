Backups

Every archive holds a full dump of the database — endpoints, history, saved queries, policies, playbooks, roles and audit. Package files are the installers staged to endpoints; they are large and re-uploadable, so they are left out unless you ask for them.

Nightly backup

Checked every fifteen minutes, so turning it on or moving it takes effect without a restart, and a server that was down at the hour still takes one when it comes back that day. One per day, oldest pruned past the number you keep. A failed nightly backup raises a critical notification rather than only a log line.

Restore

A restore replaces every row in the database with the contents of the archive, and the server restarts to come back onto it. Anything that happened since the backup was taken is gone. Restore onto a deployment whose MUSTRA_CREDENTIAL_ENCRYPTION_KEY differs from the one that took it and the stored credentials will not decrypt.

Only for an archive this server did not sign: taken by another deployment, or by a version before backups were signed. It is screened strictly before anything is applied, and anything beyond plain SQL data (shell escapes, COPY … PROGRAM, psql meta-commands) refuses the whole restore. Administrators only.
