Microsoft Entra ID and Intune

—

Reads Entra ID's devices and Intune's managed devices every hour through Microsoft Graph and joins them to endpoints (by the Entra device ID the endpoint reports, then by hostname): each endpoint shows its join type, compliance, Intune check-in and primary user, with Intune Sync and Restart buttons. Create an app registration (Entra admin center → App registrations → New), add a client secret, and grant the Microsoft Graph application permissions Device.Read.All, DeviceManagementManagedDevices.Read.All and, for the buttons, DeviceManagementManagedDevices.PrivilegedOperations.All, then Grant admin consent. Without Intune, the Entra half still works.

Agent behavior

Agent identity

—

Read-only. Changing the public URL needs the Change agent trust permission.

Public URL. The address endpoints reach this console at. Every install command, binary download and package download handed to an agent is built from it — never from the address a request arrived on, which the requester chooses. https only, unless you allow plain http for a trusted LAN or development.

Uninstall password

Asked for by the uninstaller that ships on every endpoint — Add/Remove Programs on Windows, uninstall.sh on macOS and Linux. Only the hash is stored and only the hash reaches endpoints, so the password can be changed later without anything holding a copy of the old one. Leave blank to keep the current one; clear it to remove the requirement.

What this stops is the person using the machine removing the agent because it is in their way. It is not a defence against an administrator of that machine and cannot be: anyone who can run the uninstaller can also stop the service and delete the directory. Endpoints pick up a change at their next install or update.

macOS MDM enrollment

Optional. A Mac only gets Full Disk Access without someone clicking through System Settings when an MDM it is enrolled in pushes the grant, and macOS ignores the same grant installed any other way. Enter your MDM's enrollment page here and a Mac agent that starts without Full Disk Access, on a Mac that is not enrolled, opens that page for the person signed in and asks them to install the profile. That happens once a day at most.

Leave it empty to keep the current behavior: the agent asks the person to add it under Privacy & Security by hand. The page usually carries your MDM's enroll secret, and every Mac that installs the agent gets a copy of it. Endpoints pick up a change at their next install or update.

macOS updates through the MDM

—

On Apple Silicon, macOS itself installs only with the password of a user who owns the disk, which the agent does not have. An MDM holding the Mac's Bootstrap Token can install it without one. Connect Fleet here and, after a Mac's patch job installs what the agent can, Mustra asks Fleet to install the pending macOS update. Linux, Windows, Intel Macs and app updates do not need this. Setup: docs/MACOS-UPDATES.md.

Patching with a restart option installs macOS at once and restarts the Mac. Without one, the Mac downloads it and asks the person signed in to install it. Use an API-only Fleet user with the maintainer role.

Email

The account mustra sends through, for reports and for integrations of the Email type. Mail carries what it reports on, such as hostnames and vulnerabilities, so send it to addresses you would trust with that. A server on an internal address must be on the internal destinations allowlist.

The server's certificate is always checked, and a password is only sent over an encrypted connection. Changing the server asks for the password again.

Internal destinations allowlist

        
Hosts the server may reach although they resolve to an internal address: webhooks (Connect exports, report delivery, Jump Gate notifications), Prometheus remote_write (Telemetry), syslog (audit forwarding and Connect syslog exports) and the directory's LDAP server — an in-house SIEM, Loki or a domain controller, say. Any other host may not be loopback, private, link-local or a metadata address, and a webhook to it must use https. One host name or IP address per line. Changing it needs the Change network allowlists permission. Destinations already configured when this check arrived were added for you.

        

          

        

        

          
          
        

      

    


    

      

        
Message buffer

        

          Agents never talk to this server directly — they publish to NATS, which writes every message to disk, and the
          server reads from there. That buffer is what lets the two ends fail independently: during a deploy or a restart
          the endpoints keep publishing, and the server picks up exactly where it stopped.
        

        

          Retention is how long the control plane may be down before published work is lost. What that costs
          differs by message: replaying an old sensor snapshot is worthless (only the newest matters) and replaying an
          old heartbeat is actively wrong, since it would claim a machine was alive when it wasn't. What you would
          genuinely lose is patch results and security events older than the window. Set it to how long an outage
          could plausibly go unnoticed here.
        

        

          

            
            

            

          

          

            
            
          

        

        

        

          
          
        

      

    


    

      

        
Directory

        

          Read users, groups, computers and memberships from Active Directory over LDAP so Impact can say what an
          account can reach. The bind account needs no rights beyond an ordinary domain user; nothing is ever written
          to the directory. Use ldaps:// or StartTLS — the sync refuses to send the password over plain LDAP
          unless you say so explicitly.

Endpoint metrics
—

        

          Agents collect host metrics (CPU, memory, load, filesystems, disks, network, temperatures, open files) under
          node_exporter's metric and label names, so existing Prometheus dashboards and alert rules work unchanged, and
          send them over the connection they already hold. This server labels each series with
          job, instance and instance_name (the endpoint's hostname),
          site, and any extra labels below, then pushes it by remote_write, serves it for scraping, or both.
          Endpoints pick up a change within five minutes.
        

        

          

          

          

        

        

          

            Endpoints
            The computer groups that collect. None means every endpoint.
            

          

          

            Collectors
            What to collect. None means all of them.
            

          

        


        
Remote write

        

          Pushes every batch as it arrives to a Prometheus remote_write endpoint: Prometheus started with
          --web.enable-remote-write-receiver (http://prometheus:9090/api/v1/write), Mimir,
          VictoriaMetrics or Grafana Cloud. A username with the password makes basic auth; the password alone is sent as a
          bearer token. A receiver on an internal address must be on the
          internal destinations allowlist, and only then may it use plain http. Batches wait
          in memory while the receiver is down, up to about the last eight minutes for a hundred endpoints.
        

        

          

          

          

          

            

        


        
Scrape

        

          Serves each endpoint's latest batch, with the agent's own timestamps, at /metrics/endpoints
          on this console, behind the Prometheus integration's token (Integrations):
          authorization: {credentials: <token>} and honor_labels: true in the scrape job, so each
          endpoint keeps its own job and instance. Endpoints silent for five minutes drop out.
          Either way each endpoint in scope also gets an up series, 1 while it heartbeats and 0 once it goes quiet,
          so an up == 0 alert works without Prometheus scraping it.

        Permissions
        Tick nothing for a read-only role: viewing the console needs no permission, so these gate only what changes things.
        

        

          

            Management rights
            The endpoints this role may act on. None means the whole fleet; a user holding one unscoped role is unscoped.
            

          

          

            Content sets
            What this role may use. None means all content. Manage the sets under Access.
            

          

        

        

          Built-in roles cannot be edited or deleted — admin and user are what the
          product guarantees they mean, and a console where “admin” had quietly been redefined would
          be worse than one with no roles at all. They are also rewritten on every server start, so an edit
          would not survive a restart. Use duplicate to edit on the role's row for a copy you own.
          


          A role with no permissions is read-only, not powerless: every signed-in user can see
          endpoints, sensor data, deployments and findings. Permissions gate only the actions that change
          something — which is what the built-in user role is.
