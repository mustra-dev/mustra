Software packages

A package says how to install, update and remove one piece of software on each platform, and how to recognize it. Every endpoint is then classified before anything runs, so deploying only touches machines the operation actually applies to.

New software package

Commands run with the agent's full rights through the platform's own shell — sh -c on Linux and macOS, PowerShell on Windows — so pipes and && work as written. On macOS a brew command is automatically run as the account that owns the Homebrew prefix, since Homebrew refuses to run as the root the agent is.

Files

Payloads staged to the endpoint before the command runs. The command runs in the staging directory, so msiexec /i setup.msi /qn means the file you upload here; $MUSTRA_PACKAGE_DIR holds the absolute path. Each file's SHA-256 is checked on the endpoint after download — a file that silently truncated is worse than one that failed to arrive, because the command would run against it anyway.

Parameters

Typed values substituted into the command as $(name) before it runs, so "restart in N seconds" is one package instead of one package per N. They are resolved before any endpoint is targeted, so a bad value stops the deployment rather than reaching half the fleet as a half-substituted command. Supplying one is as privileged as writing the command itself, so a package with parameters is not offered through Self Service.

Limits

The timeout is how long the command may run on the endpoint — the right answer differs enormously between flushing a DNS cache and installing an office suite. Expiry stops a deployment being worth attempting at all, so one aimed at a machine that is switched off does not fire at 3am three weeks later.

"Must be run against endpoints you select" removes the option to run this package fleet-wide. Worth setting on anything a second run cannot undo — removing the agent, most obviously, which also removes the means of putting it back. The server refuses an untargeted run either way, so an API token cannot route around it.

Every installed application, normalised to one product across platforms and versions, graded by how often it actually runs. Usage comes from the process starts the fleet already reports and from what the endpoint itself records (Windows Prefetch, Spotlight); nothing extra runs on the endpoint. Unused means mustra knows what the product runs as and saw no launch in the window; unknown means it cannot tell (a library, a runtime, or no known executable — add one on the tracked product). Track a product to price it: cost per seat × installed is the estimated annual cost, × unused the estimated waste. Levels are graded against the usage history that exists (shown in the status line) until it reaches the window, so they settle over the first weeks. Remove unused hands the unused endpoints to the product's catalog package as an ordinary remove deployment, maintenance windows and all.

Confidence

What this fleet's own history says about a package: how often it has actually worked here, on how many machines, and what it did to their health in the day after. Some tools compute part of this from data pooled across every customer; mustra has no such corpus and inventing one would be a lie, so this is local only.

A package with too little history reports not enough history rather than a number. Three successes out of three is not certainty, it is no evidence, and a score shown without its sample size is worse than no score because it looks like knowledge. A fall in health after a deployment costs a package points, capped, and a rise earns it none — a machine's week improving is not the package helping.

Scheduled actions

Run a package on a cadence. Firing one goes through exactly the same path as deploying it by hand — applicability is evaluated fresh, parameters are resolved and validated, files are staged — so a schedule cannot quietly behave differently from the thing you tested. Times are UTC.

A window restricts only the endpoints it targets (on its platform); an endpoint no window covers is unrestricted, and one covered by several may be touched while any of them is open. A queued deployment outside its window waits and says so; a patch run skips the endpoint until the next firing inside the window. Only an account holding deploy.override_windows can deploy outside a window.
