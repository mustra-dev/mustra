A MAC address the boot server knows. Any other machine that network-boots is told to boot its own disk. Install next boot arms a machine once: its next network boot installs its image, and fetching the answer file disarms it. An unused arming lapses on its own. A MAC that a managed endpoint reports cannot be armed here: use Reimage, which asks for the hostname and a second person's approval.

Reimage an endpoint

Assigns an image to one endpoint's network interface, arms it, and asks its agent to boot from the network once: efibootmgr --bootnext on Linux, the firmware boot sequence through bcdedit on Windows, both on UEFI. Where neither works the answer says so, and somebody at the machine picks network boot (usually F12). The request always waits for a second person with the approvals permission (Access → Approvals) and is audited.

This erases the endpoint's disk. Everything on it is lost; the installed system enrolls as a new endpoint.

Images

An installer the boot server can start. Boot files are each a URL the machine downloads itself, or a file uploaded here and served by mustra without authentication — so upload nothing secret. mustra bundles no installation media: point Windows images at your own WinPE files and a share holding your installation media. Ubuntu uses the live-server ISO's casper/vmlinuz and casper/initrd with the ISO's URL as the install source; Debian the netboot linux and initrd.gz with a mirror.

Answer template

Blank uses the built-in template for the family. A template is Go text/template; write every value through the escaper for its format — yaml, line (preseed), xml, sh — as the built-in ones do. It is test-rendered when saved.

Boot server

The boot endpoints under /boot/ serve iPXE scripts and boot files without authentication — firmware has nothing to authenticate with — and answer files only to the per-install token in a boot script, once, before it expires. Limit them to the provisioning networks, and set MUSTRA_BOOT_HTTP_ADDR to serve them on a listener of their own rather than wherever the console is published.

Chainloading from your DHCP server

mustra runs no DHCP or TFTP server. Point your existing DHCP at an iPXE binary (option 66, the TFTP server; option 67, ipxe.efi for UEFI or undionly.kpxe for BIOS), and hand clients that already run iPXE this script instead, or build it into iPXE with EMBED=. A proxy-DHCP example with dnsmasq is in the deployment guide. iPXE is not signed for Secure Boot by default: turn Secure Boot off on machines you install this way.
